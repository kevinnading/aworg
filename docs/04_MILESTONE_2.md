# AWORG Milestone 2

## Goal

Make the relationship workable:

> **The owner can read what the Resident says, see where it lives, and
> has a place ready for whatever it eventually builds.**

Milestone 1 made the Resident present. It could hold a conversation that
survived restarts and could change the mind behind it without losing
itself. But it was still only a chat window, and a Resident that is
going to develop software cannot live in a chat window.

The Resident gains no new abilities in this milestone. What changes is
the owner's ability to work with it.

## The Experience

The owner opens AWORG and sees one screen rather than a set of pages.

The application the Resident is responsible for sits in the upper left.
Beneath it is the Living Workspace — everything the Resident has made.
The conversation occupies the whole right side.

This arrangement makes a claim about what AWORG is. Chat is not a page
the owner visits; it is the layer they work through. What the Resident
has built belongs permanently in view beside the conversation, not
behind a tab the owner has to remember to check.

### Replies That Can Be Read

The Resident's replies are rendered rather than dumped as raw text.
Structure appears as structure: headings, lists, emphasis, quotes.

Code appears as code — set apart, numbered, coloured, and copyable in a
single action.

This is not decoration. The Resident is a software developer. A
developer who cannot show work legibly is difficult to work with, and
that is true well before it can write anything itself. The owner will be
reading a great deal of what this Resident produces; it should be
readable.

### The Workspace in View

The Living Workspace is visible and follows along as it changes. The
owner can move through it, see what exists, and watch things appear and
disappear as work happens.

The important word is **watch**. The owner should never have to take the
Resident's word for what it did. Being able to see the workspace
directly is the beginning of a habit that matters enormously later: when
the Resident begins repairing things on its own, the owner's trust will
rest on being able to check.

The workspace is also a real boundary, not a convention. What lies
outside it is not the Resident's territory and is not shown.

### A Place for the Application

A preview area waits for whatever the Resident eventually runs.

It is deliberately honest while empty. It says plainly that no
application exists yet and why, rather than showing a blank frame that
looks broken. An interface that lies about being unfinished teaches the
owner not to trust it.

It stays modest for now. The commanding, full-width preview belongs to a
later dashboard, once there is a running application worth giving the
room to.

### The Feel of the Place

AWORG should look like somewhere software gets made.

Recognisable colour, type, and iconography do real work here: a file
type identified at a glance, a code block that reads as code instantly,
a listing that can be scanned rather than read. These conventions exist
because they are effective, and adopting them costs nothing.

The owner may never write a line of code. They will still be living
inside a workshop, and a workshop should look like one.

## What This Milestone Does Not Do

The Resident still cannot act. It has no tools, cannot read or change
files, and cannot run anything. The workspace it can be watched in is
one only the owner can put things into.

That limitation is deliberate. The surfaces the Resident will act
through are built and proven first, so that when it does begin to act,
the owner can already see it happening.

## Milestone 2 Is Complete When

The owner can hold a real working conversation with the Resident —
reading explanations and code comfortably, without copying text
elsewhere to make sense of it — while the workspace and the application
area remain in view beside it, honest about being empty.

## What Comes Next

Milestone 3 gives the Resident the **ability to act**: to create,
inspect, change, and run things inside the Living Workspace rather than
only discuss them.

That is the step that turns a Resident who can talk into a Resident who
can build.
